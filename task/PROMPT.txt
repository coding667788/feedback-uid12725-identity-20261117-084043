为安全审计设计一个可恢复的本地追加日志。威胁模型是攻击者能修改日志文件，但不能改验收方离线保管的检查点及其HMAC密钥。

请从空目录实现以下可运行工具。环境为 Windows、Python 3.12、仅CPU；不使用Docker或真实外部服务。除题面明确允许的cryptography外只用标准库。输入样例、模拟组件和测试数据由你在项目内构造，不存在另行提供的附件。

核心要求：
1. 事件采用长度前缀、单调序号和规范化JSON，每条哈希覆盖上一条哈希与当前原始记录；段尾封存段范围、前段根和本段根。可信检查点包含最后封存段号、末序号、根及HMAC，验证器必须显式接收检查点，不能信任日志自带的同名文件。
2. 恢复只允许截掉最后未封存段的不完整尾记录，已封存段或段内完整记录损坏必须报错；区分合法崩溃尾、篡改、整段删除、重排与尾部回滚。对检查点之后但尚未锚定的完整尾段只报告未锚定，不能宣称真实性已证实。
3. 追加进程用单写者锁，封存及检查点导出采用临时文件和原子替换；记录持久化边界，在每个边界可注入退出并恢复。验证器流式读取，不把整个日志载入内存，输出首个失败偏移与最长已验证前缀。

必须覆盖的验收场景：截断任意字节、交换两段、删除中段、替换旧副本、合法未锚定尾段与封存中崩溃；正常百万事件验真内存随单条最大长度有界。

交付源代码、README、样例及自动化测试。提供 python -m solution --input cases.json --output result.json 和 python -m unittest discover -s tests -v 两个入口；cases.json可引用项目内源文件或二进制样例。输入输出schema、错误码及未写明的非安全性细节自行设计并完整说明，不能放宽上述要求。测试必须断言具体结果、状态或证据，不能只打印成功；固定种子可重放。所有操作局限在项目测试目录和本机模拟服务。
